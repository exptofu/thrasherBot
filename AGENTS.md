# Project guidance

- `bot.py` polls eBird for notable sightings and posts grouped sightings to a Discord forum; SQLite stores state. `groups` tracks one message per species per checklist group (`checklist_id`, `scope`, `message_id`, `thread_id`). When a submitter edits a checklist's location, `send_group()` must update the message where it actually lives: delete the stale non-starter message and repost in the corrected hotspot/county thread. A stale message that is a thread starter is kept and its embed is edited with a "moved" notice instead, because deleting a forum starter deletes the whole thread.
- `mark_missing_sightings()` waits for `MISSING_POLLS` consecutive notable-feed misses (default 3), then uses `product/checklist/view/{subId}` to classify the post: still listed + unreviewed → `⚠️ No longer in RBA`; still listed + reviewed → keep Confirmed/Rejected and set `rba_checked`; species absent or checklist 404 → `🗑️ Removed from checklist`. Reviewed records are only checked once per absence (`MISSING_CHECK_LIMIT` per poll). Lookup failures leave the post unchanged and retry next poll. Absence alone is not proof: the feed can transiently omit records. `update_existing_sightings()` clears the counter/status/`rba_checked` when the sighting reappears.
- `REGIONS` in `bot.py` maps every Georgia county to one of at most 20 regions (Discord's forum tag limit). Each region is a forum tag and has a `<region>-chat` text channel; each category has a `<category>-rba` forum, and the bot posts sighting links in the county's region chat. `REGION_GROUPS` assigns every region exactly once to a category; preserve category order and all 159 unique county assignments. Keep `georgia_map.py` definitions and colors in sync.
- `georgia_map.py` renders `georgia_regions.svg` using only the standard library. Its `REGIONS`/`REGION_GROUPS` must match `bot.py`. `utils/region_channels.py` is an apply-only standalone job for tags, channel creation, permission syncing, and ordering; `bot.py` does not run it on startup. It does not delete obsolete tags or channels. `utils/sync_category_permissions.py` is a preview-first temporary utility; it syncs all categorized guild channels except the forum ID in `DISCORD_CHANNEL_ID`. `utils/archive_orphaned_posts.py` is a preview-first job that archives bot-created alert-forum threads whose sightings are no longer in SQLite, which `bot.py`'s automatic archive pass cannot see; it never touches member-created or pinned posts. See `docs/regions.md` for migration behavior.
- Keep changes focused and follow the existing single-file structure unless a feature clearly needs a separate module.
- Read configuration from environment variables. Never commit credentials; update `.env.example` when configuration changes.
- Preserve API request pacing/retries and take care with SQLite schema changes, since the database may contain live bot state. Prefer guarded additive migrations (`PRAGMA table_info` + `ALTER TABLE`, as with `groups.thread_id`) over bumping `SCHEMA_VERSION`, which drops the live `sightings`/`posts` tables.
- Dependencies belong in `requirements.txt`. Avoid adding a dependency for behavior the standard library already handles.
- There is no test suite yet. For Python edits, run `python -m py_compile bot.py utils/region_channels.py utils/sync_category_permissions.py utils/archive_orphaned_posts.py georgia_map.py` and add or run a focused behavior check when practical.
